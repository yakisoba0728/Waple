## 한 줄 요약

원본 바이너리의 **파티클 오퍼레이터 VM**(`0x14023fbc0 .. 0x14024be38`)을 처음으로 끝까지
읽었고, 그 결과 **"부호는 맞는데 모양이 틀린"** 발산 다섯 건이 나왔다. 골든 기준선은
그 틀린 그림을 정답으로 박아 두고 있었다.

## 구조 — 이걸 모르면 계속 틀린다

파티클 오퍼레이터는 C++ 객체도 vtable 도 아니다. **아레나에 범프 할당되는 바이트코드 레코드**다.

```
레코드: [+0x00] u8 opcode · [+0x02] u16 크기 · [+0x10] 페이로드
디스패치: 0x14023fd6c  movzx eax,[r14]; jmp jumptable[eax-1]      ; 테이블 @0x14024bb58
전진:     0x140240279  movzx eax, word[r14+2]; add r14, rax
```

### 함정 넷 (전부 실제로 밟았다)

**① `.pdata` 조각을 함수로 보면 안 된다.** 인접 병합도 과병합을 낸다
(`Json::Value::find` 가 11조각으로 잘못 묶인다). `UNWIND_INFO` 의 `UNW_FLAG_CHAININFO` 로
primary 에 귀속해야 한다. `vortex_v2` 는 조회 주소가 속한 조각의 시작이 진입점이 아니라,
그 조각만 읽으면 수치 주입 12개 중 11개를 놓친다.

**② 같은 원소에 핸들러가 둘이다.** 할당기가 먼저 **잠정** opcode 를 찍고, 페이드 창 게이트를
통과할 때만 공용 파서가 ext 로 덮어쓴다. `controlpointattract` 는 0x0a→0x140241554 /
0x20→0x14024172d, `maintaindistancetocontrolpoint` 는 0x0b→0x14024197a / 0x21→0x140241ccf.
**한쪽만 보고 "다른 원소" 라고 판단하면 안 된다** — 실제로 그럴 뻔했다.

**③ 주입과 소비는 다르다.** 주입기는 부재 키를 JSON 에 무조건 심지만, 핸들러가 그 값을 쓸지는
별개다. `vortex_v2` 의 ring 4키는 항상 주입되지만 `flags & 4` 없이는 **레코드에 실려도 힘이
되지 않는다**(런타임 `test byte [r14+0x110], 4` @0x1402434eb). 이걸 놓쳐 한 번 회귀를 냈다.

**④ "호출부를 센다" 가 아니라 "인자를 싣는 곳을 센다".** 페이드 창 대상을 공용 파서
호출부 11곳으로 세어 11종이라 적었는데 **13종**이다. 두 원소가 `mov r9d, <opcode>` 뒤
`jmp` 로 다른 원소의 호출부에 뛰어든다. `mov r9d, imm` 을 세면 13곳이 0x1c..0x28 로 연속이다.

## 고친 발산

| 항목 | 종전 | 실측 | 도달 |
| --- | --- | --- | --- |
| 소용돌이 접선 | `cross(axis, radial)` | **`cross(n, axis)`** — 부호 반대, **거꾸로 돌고 있었다** | vortex 14 인스턴스 전건 |
| 접선 정규화 | `normalizeSafe` | 정규화 **없음**(`\|n×a\| = sinθ` 가 남는다) | 위와 같음 |
| 축 투영 | 항상 | `flags & 1` 일 때만(`andps` @0x140243316) | 동봉 9건 중 7건이 미투영 |
| `dOut == dIn` | 램프 없음(t=0) | invRange **1.0**(폭 1 램프). `dOut < dIn` 은 역램프 | 픽스처 의존 |
| 소용돌이 중심 | `offset` | **CP 위치 + offset**(v2 는 CP 만) | 동봉 전건 CP 원점이라 0 |
| `centerforce` | 축을 향한 등가속 인력 | **반경속도 감쇠** `v_r *= (1−cf)`, dt 상쇄, 정지 입자엔 무작용 | v2 5건 중 4건 |
| `centerforce`/ring 게이트 | 없음 | `flags & 2` / `flags & 4` | ring 은 동봉 도달 **0** |
| `controlpointattract` 감쇠 | `min(1, threshold/dist)` 포화 | **`1 − dist/threshold` 선형 램프 + 하드 컷오프** | 동봉 35건 전건 |
| `controlpointattract` 대상 키 | `origin` | **`offset`**("origin" 은 이 구간에 참조 0) | 실코퍼스는 둘 다 (0,0,0) |
| 오버슛 클램프 | 없음 | `flags & 2`(기본 ON): `step = min(step, dist)` | 동봉 34건 |
| 페이드 창 기본 | 0/0/0/0 | 0/0/**1**/**1** + 활성화 게이트(0.01/0.99) | 13 인스턴스 |
| `speedouter` 부재 | `speedinner` 승계 | **0.0**(`xorps`, 플래그 무관) | v1·v2 |
| `inheritcontrolpointvelocity.scale` | 기본 1 | **그런 키 없음**. 실물은 `min`(0.1)/`max`(0.2) | 도달 0 |

### 착지한 원소

- **`maintaindistancetocontrolpoint`** — 종전 드롭. Magic "Vortex orb" 의 구각이 통째로 없었다.
  `pos += (distance/\|d\| − 1)·s·d`, 속도는 안 건드린다. "CP 지원 없으면 no-op" 이라는 판단이
  이 원소엔 **거짓**이다(퇴화 가드가 없고, 유일한 실사용처의 CP0 이 시스템 원점이라 지금도 성립).
- **`boids`** — Water "Dripping water" 2종. 서브샘플링(`N = count/100+1`, 4-입자 그룹 위상)과
  제자리 갱신까지 옮겼다.
- **페이드 창** — `remapvalue` 하나에서 **turbulence·capvelocity·oscillatealpha·oscillateposition**
  까지. 그 넷 + remapvalue 가 도달 13건 전부다.

## 일부러 안 한 것

| 항목 | 왜 |
| --- | --- |
| ring 힘 수식 | 실측 형태(대역 폭이 `ringWidth` 전체, 대역 밖 선형 램프, `radial′` 에 비례)를 확보했지만 **`flags & 4` 를 가진 인스턴스가 동봉에 0건**이라 검증 우선순위가 낮다. [추정] 표기 유지 |
| `deletethreshold` 본체 | 실물은 점–점이 아니라 **직전→현재 위치 선분과 CP 의 최단거리²** 비교이고 `age = lifetime` 대입으로 표현한다. `flags & 1` 게이트만 먼저 맞췄다 — 기본 flags 2 에 bit0 이 없고 동봉 35건이 키를 전건 생략해 **양쪽 다 무동작**이다 |
| `controlpoint` 부재 시 CP0 바인딩(attract) | 대상이 원점에서 씬 CP0 으로 옮겨 가는 변경이라 런타임 측정이 더 필요하다 |
| `dtScaled` | 실물은 `dt·min(1, 0.025/[ctx+0x14c])^0.7` 를 쓰는데 `[ctx+0x14c]` 의 정체가 **미확정**이다. dt ≤ 0.025(≥40fps)면 `dt` 와 같으므로 영향이 제한적이다 |
| `inheritcontrolpointvelocity` 시뮬 | **RNG 를 1회 드로**하므로 구현하는 순간 이후 이니셜라이저의 난수 시퀀스가 통째로 밀린다. 골든 재베이스라인과 묶어야 한다 |
| 나머지 8종의 페이드 창 소비 | 도달 0 |
| `collisionbox` | **구현 금지.** opcode 0x17 의 핸들러가 VM 의 명령어 전진 라벨(0x140240279) — WE 자신이 no-op 다 |
