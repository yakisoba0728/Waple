### 검증 체계 — 이 세션의 실질

시작 시점에 **픽셀 회귀를 자동으로 잡는 장치가 0개**였다. 지금은 CI 가 지킨다.

- **합성 씬 픽셀 골든**(`SyntheticPixelGoldenTests` + `spec/golden/synthetic/`).
  코퍼스가 필요 없어 CI 에서 돈다. 실측 `meanAbsDiff=0.0` — 완전 결정적이다.
- **스킵 트립와이어**. `XCTSkip("no Metal")` 아래 561개가 GPU 없는 환경에서 전부
  스킵돼도 CI 는 초록을 찍었다. 이제 스킵 상한 100 · 실행 하한 2,285.
- **구성 매트릭스**. release 를 CI 에서 한 번도 세운 적이 없었다 —
  세워보니 `@testable import` 가 구조적으로 못 서고 있었다(`-enable-testing` 필요).
- **Linux spec 잡**. `validate.py` 도 spec 테스트도 한 번도 안 돌았다. 매니페스트
  무결성·EOL 속성 검사를 여기서 한다.
- **블렌드 32종 커버리지**. 픽셀까지 구동되던 것이 3종뿐이었다.
- **공용 바이너리 리더 경계 테스트**. `BinaryReading.swift` 는 테스트 참조가 0건이었다.

## 🛑 함정 — 이 문서의 값어치는 여기다

직전 인계 문서도 같은 말을 한다. 아래는 이번 세션에서 **실제로 밟은** 것들이다.

### 1. 격리 애너테이션이 `@objc` 콜백을 조용히 끊는다

`-strict-concurrency=complete` 를 **경고로** 켰을 뿐인데 웹 내비게이션 보안 게이트가
죽었다. SDK 가 완료 핸들러에 붙인 동시성 애너테이션 때문에 우리 시그니처가
optional 요구사항과 어긋나 **witness 자격 → 암묵적 `@objc` → 셀렉터**를 차례로 잃고,
`respondsToSelector:` 가 NO 를 반환해 WebKit 이 기본값 `.allow` 로 갔다.

컴파일 오류 없음. 경고 한 줄. **코드를 읽어서는 절대 못 찾는다** —
악성 내비게이션을 실제로 시도하는 테스트만 잡는다.

해법은 **async 델리게이트 구현**이다. 앞선 두 우회는 실패했고 그 기록이
`WebRenderer.swift` 의 해당 메서드 주석에 있다. **완료 핸들러 형태로 되돌리지 마라.**

같은 위험에 노출된 것: 프레임워크가 셀렉터로 콜백하는 모든 타입.
`required` 요구사항은 불일치가 컴파일 오류로 드러나므로 안전하고,
**`optional` 만 조용히 실패한다**.

### 2. 확장자·디렉터리를 열거하면 반드시 하나를 놓친다

`.gitattributes` 가 WEAssets 텍스트를 확장자별로 `-text` 지정했는데
`*.json` 이 `foo.tex-json` 에 매치되지 않았고(`json` 앞이 `-`), `*.js` 는 목록에 없었다.
302개가 손상됐다.

이번에 골든 이미지 규칙을 추가할 때 **같은 함정 앞**이었다 —
`spec/golden/snapshot/**` 이 아니라 `spec/golden/**` 으로 덮었다.

### 3. "검사하는 척하는 검사" 가 이 리포의 지배적 결함 유형이다

버그 자체보다 이게 더 많았다.

- `mip_filter` 테스트가 이름이 다른 샘플러(`fbSampler`)를 못 봤다 — 결함이 살아 있는
  동안 계속 초록이었다
- `XCTAssertTrue(true)` 한 줄 (`.mdl` 픽스처가 8바이트 매직뿐이라 대상 경로에 닿지도 않음)
- 골든 오라클이 `manifest.json` 을 **자기 자신과** 대조
- `SnapshotTests` 가 비교 로직을 인라인 재구현해 **자기 산수를 단언** — 프로덕션
  로직을 지워도 통과
- `/tmp/waple_gt/luma_baseline.json` 은 없으면 만들고 통과 → 새 머신에서 영원히 실패 불가

**그래서 이번에 추가한 모든 검사에 음성 대조를 붙였다.** 빨강/파랑 프레임이 통과하면
실패시키고, "opacity 무시" 단언에는 opacity 에 반응해야 하는 대조군을 두고,
기준선 부재는 스킵이 아니라 실패로 만들었다. 검사를 추가할 때 **그 검사가 무엇을
못 잡는지**를 먼저 적어라.

### 4. `continue-on-error` 는 잡 결론을 속인다

release 레인의 테스트 실패를 "release 는 통과" 로 잘못 읽었다. 잡 `conclusion` 은
`success` 인데 로그에는 `2 failures` 가 있었다. **잡 결론이 아니라 로그를 봐라.**

### 5. 에이전트 보고를 그대로 믿지 마라

문서 결함 9건 중 **4건은 지적이 틀렸다** — 이력 로그의 과거 항목을 현재 주장으로
읽거나, 다른 대상(`waple-baselines/` vs `spec/golden/snapshot/`)을 혼동했다.
`baseline-7075b74` 는 6곳에 있었는데 **실제 결함은 1곳뿐**이고 나머지는 역사였다.
일괄 치환했으면 이력을 위조했을 것이다.

반대로 에이전트가 **내 진단을 반증한** 경우도 있다(§1 의 "적합성이 통째로 깨졌다" 는
틀렸고, 완료 핸들러를 가진 메서드 하나만 떨어져 나간 것이었다).

## 남은 것

코드로 밀 수 있는 것은 소진했다. 남은 둘은 **결정**이 필요하다.

### A. `LICENSE` 예외 조항 — 소유자 결정

`LICENSE` 는 예외 없는 순수 MIT 인데 WE 에셋 75.8MB 를 동봉해 배포한다.
문면상 작성자가 라이선스할 수 없는 것을 서브라이선스하는 형태다.

이번 세션은 **사실관계만 바로잡았다**(`NOTICE`·README 의 거짓 진술).
조항을 쓰거나 동봉 방침을 바꾸는 것은 하지 않았다. 선택지는 셋으로 보인다 —
예외 조항 추가 / 동봉 중단(현재는 `package-app.sh` 가 에셋 없으면 릴리스를 **실패시킨다**) / 현상 유지.

### B. Swift 6 `.v6` 전환 — 설계 변경 필요

진단 265건 → 70건(74%)까지 줄였다. 남은 70 중 약 45건이 `AppDelegate` 의 **F486
오프메인 마운트 경로**다. 애너테이션으로 없애면 실측으로 수초 스톨을 고친 최적화가
되돌아간다.

진짜 해결은 캡처 경로를 `RendererFactory` 에서 분리하거나 뷰 없는 오프스크린 타깃으로
옮기는 것인데, 성능 실측을 다시 떠야 한다. 현재는 `-strict-concurrency=complete` 가
**경고로** 켜져 있고 CI 가 파일별 건수를 잡 요약에 렌더한다 — 그 숫자가 0 이 되면
모드를 올릴 수 있다.

렌더러에 `@MainActor` 를 붙이는 것이 ~50건의 정답이지만 **테스트 타깃과 한 커밋이어야
한다**. `SceneRenderer` 만 85파일 420곳이 nonisolated XCTest 메서드에서 참조한다.

## 재현·검증

```bash
# CI 가 하는 것과 같은 것
swift build -c debug && swift build --build-tests -c debug && swift test --skip-build

# release 는 테스트 빌드에 플래그가 필요하다(§CI 매트릭스 주석 참조)
swift build --build-tests -c release -Xswiftc -enable-testing

# 픽셀 골든 기준선 다시 뜨기 — 눈으로 확인하기 전에 커밋하지 마라
WAPLE_GOLDEN_BOOTSTRAP=1 swift test --filter SyntheticPixelGolden
# 또는 GitHub Actions 에서 CI 워크플로를 golden_bootstrap 입력을 켜고 수동 실행
```

기준선 넷의 기대 픽셀 값은 `spec/golden/synthetic/README.md` 에 있다.
