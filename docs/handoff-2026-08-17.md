## A. `wip/shape-quad` — 골든의 관문 (1순위)

### 상태
| 커밋 | 내용 |
| --- | --- |

⚠️ **`d92f99b` 의 제목이 "WE 기본 크기 확정" 을 단언하는데 그 등급이 아직 안 선다.**
아래가 닫히기 전에는 제목·등급을 낮춰야 한다. "확정" 이라고 적힌 채 두는 것이 가장 나쁘다.

### 이미 확정된 것 (뒤집을 근거 없으면 신뢰)
- `"quad"` 문자열이 WE 바이너리 **5종 어디에도 없다**(ASCII·UTF-16 0건).
  shape 분기는 JSON **타입 태그**(=4)만 보고 값을 비교하지 않는다 → shape 값은 미해석.
- shape 렌더러블(0x460B, vtable `0x140491D10`)의 vfunc `+0x40` 이
  `(float)(int32)[ctx+0x88]` 을 `this+0x2F0` 에 **movsd**(float 2개)로 쓴다.
- `ctx+0x84 = (int)ortho.width`, `ctx+0x88 = (int)ortho.height`(공유 필드 `+0x11c` 로 교차 확인).

### 남은 것
1. **`this+0x2F0/0x2F4` 의 소비 지점** — "그 필드가 크기다" 를 세우는 열쇠이자 등급을
   추정에서 올리는 유일한 길. 이미지 레이어는 별개 클래스(0x960)라 대조 불가.
2. **교란 ①** `3521337568` 쿼드 부모(id **2065**) scale 미확인 — 부모 변환이 개입하면
   기본 크기와 무관하게 결과가 갈린다.
3. **교란 ②** 비-풀스크린에서 우리 솔리드 레이어 이펙트 체인의 UV/RT 규약 미검증 —
   직전 산출물에 **WE 엔 없는 하드 엣지**가 있었다(WE 는 rayfeather 페이드).
4. 4씬 육안 대조: `3404976219` · `3521337568` · `3558034522` · `3460973721`.
   **`3299228616` 무회귀 확인 필수**(이미 해결된 씬이다).

### 함정 (실제로 걸렸던 것)
- 측정 스크립트는 `WE_BIN` 만으로는 죽는다(`형제 바이너리를 하나도 못 찾았다`).
  형제 5종이 한 디렉터리에 있으니 **`WE_ROOT` 로 줘라**:
  ```bash
  WE_ROOT=~/Downloads/wallpaper_source/binaries \
  WE_WORKSHOP=~/Downloads/wallpaper_dev/backgrounds \
  python3 scripts/spec/measure_shape_quad.py
  ```
  단 그 디렉터리는 설치본 레이아웃이 아니다(`assets/` 없음). 다른 생성기의 `WE_ROOT`
  관례를 깨지 말고 폴백을 더할 것.
- **PE 스큐**: 보관본 `wallpaper64.exe`(5,360,320B)는 e_lfanew 0x110 이고 섹션 테이블
  `PointerToRawData` 가 갱신 안 돼 **208B 어긋난다.** 헤더대로 읽으면 `.pdata` 가 전부 0.
  `measure_texture_filtering.py` 의 `PE` 리더가 보정 코드를 갖고 있다. 깨끗한 설치본은 5,360,112B.
- RenderDoc 은 **1개뿐**이다(`caps/` 없음), 섹션 압축이라 desc 바이트 스캔은 이미 실패했다.
