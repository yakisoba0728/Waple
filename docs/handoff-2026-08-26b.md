## 2. 직전 라운드 지시를 뒤집은 것 — **먼저 읽어라**

직전 §2-④ 는 "실제 VA = 인용값 **+ 0xD0**, Waple 소스 주석의 핸들러 VA 인용 20여 개가
교정 대상" 이라고 적었다. **둘 다 틀렸다.**

- **부호가 반대다.** 코퍼스가 `X` 라 부른 주소의 실제 내용은 `X − 0xD0` 에 있다.
  `.pdata` 실측 시작점 14,792 개를 진실 집합으로 놓으면 코퍼스 교집합은
  그대로 0.76% · `+0xD0` 1.29% · **`−0xD0` 29.24%** 다.
- **Waple 소스는 교정 대상이 아니다.** 규모는 "20여 개" 가 아니라 실측 **6,053 인용 지점 /
  4,140 고유 VA / 63 파일**이고, 모호성 없는 508 표본을 역어셈블하면 **인용값 그대로가
  88.4%** 로 맞는다(`−0xD0` 은 6.5%, 잡음). 그 좌표들은 손상된 코퍼스가 아니라 직접 PE
  파싱에서 나왔다.
- **"점프테이블 base 0x1400000D0" 은 유령이다.** 그 주소들 자체가 코퍼스 좌표라서 생긴
  착시다. 무손상 원본에서는 `lea r9,[rip-0x23fd77]` → `0x140000000`(`__ImageBase`)이고,
  `.text` 전역에서 `0x140000000` 을 겨냥한 `lea` 는 597건, `0x1400000D0` 은 **0건**이다.
  표준 MSVC x64 점프테이블이므로 `handler VA = table raw + 0x140000000` — 소스 주석이
  이미 쓰던 값이다.

**무손상 원본은 저장소에 있다.** 직전 라운드가 "재생성 경로 없음" 을 전제했는데 틀렸다.
`wallpaper_engine/wallpaper64.exe` 와 `wallpaper_engine/distribution/wallpaper64.exe` 둘 다
5,360,112B · md5 `438cb215f20a8f6c38f57fbc3d9da588` 로 추적 중이고, 섹션표 그대로
`.pdata` 가 14,792/14,792 파싱된다. 손상된 것은 `binaries/` 뿐이다. **코퍼스 재생성은
오늘 가능하다** — 그게 다음 RE 라운드의 첫 단추다.

## 3. 신규 발견 — 어느 감사 문서에도 없던 것

### ① 리눅스 타입체크 게이트가 원본부터 죽어 있었다 (`1592004`)

`AGENTS.md` 가 "커버 55/55" 라 적어 둔 안전망이 원본 HEAD `eecc889` 에서 **rc=1 로 죽는다**
(CI 와 같은 Swift 6.3.2 로 확인). 원인은 `linux-shim/metalkit.swift` 의 `MTKViewDelegate` 에
격리 표기가 없던 것. macOS 만 초록이라 아무도 몰랐고, 그 사이 **소스 55 · 테스트 154 ·
앱 80 · CompatCore 11 · 라이브러리 16 파일이 한 번도 검사되지 않았다.**

심 형태는 네 변형을 실측해 골랐다 — 자세한 근거는 커밋 메시지에. 요점만: 프로토콜 전체에
`@MainActor` 를 붙이면 **전역 액터 추론**으로 `SceneRenderer` 가 통째로 격리되어
`SceneRenderer.swift:1937`·`:1969` 의 명시 금지와 부딪힌다. 실물과 같은
`@preconcurrency @MainActor` 가 맞다(`swiftui.swift:52` 에 같은 선례가 있다).

### ② `--app` 이 조용히 통째로 건너뛰어지고 있었다 (`1592004`)

`--app` 블록이 `if [ $trc -eq 0 ]`(렌더 테스트 통과) 안에 있어서, `Tests/WapleRenderTests`
가 한 군데만 깨져도 앱 계층 80파일이 **한 파일도 못 본 채** 건너뛰어졌고 로그에 흔적이
없었다. 종료코드는 그대로 두고 분리했다 — 덜 실패하게가 아니라 더 보게 만드는 변경이다.

### ③ `supportsAudioProcessing` 도 소비자가 0이다 (`5a7831b`)

`playbackProperties` 만의 문제가 아니었다. 14필드 중 이 둘만 프로덕션 참조 0이고, 이쪽은
테스트 9건이 단언까지 해서 살아 있어 보였다. `ProjectJSONParser.swift` 의 "오디오
파이프라인 전체의 마스터 게이트다" 는 거짓이었다 — 실제 오디오는 `SceneRenderer.hasAudio`
가 켜고 그 값은 프로젝트 선언이 아니라 **씬 내용 검사**(`scriptWantsAudio`)에서 온다.
즉 Waple 은 WE 의 선언 게이트를 존중하지 않는다. 배선할지 "의도적 미사용" 으로 재분류할지는
사람 결정으로 남는다.

## 4. 이번 라운드가 스스로 만든 결함과 그 처리

**정직하게 남긴다 — 다음 라운드가 같은 실수를 하지 않도록.**

- **이중 옵셔널 `??` 죽은 폴백.** `with(previewName: a ?? b)` 에서 파라미터가 `String??` 라
  좌변이 승격되고 **우변이 죽는다**. 컴파일러는 경고만 내므로 빌드는 서고 규약만 사라진다.
  `5a7831b` 가 그 상태로 나갔고 다음 커밋에서 고쳤다. 타입 명시 지역 상수로 먼저 접을 것 —
  `WallpaperProject.with(...)` 주석에 경고로 박아 뒀다.
- **원인은 절차였다.** 에이전트가 보고를 보내기 전에 작업 트리를 "완성" 으로 보고 커밋했다.
  **에이전트 산출물은 보고를 받고 커밋한다.**
- **검증 스크립트를 `flock` 으로 감싸지 마라.** 스크립트가 `:226` 에서 같은 락 파일을 스스로
  잡는다. 감싸면 데드락이고, 고아 파이프 단계가 파일 서술자를 살려 락이 영영 안 풀린다.
- **툴체인은 `PATH` 가 아니라 `WAPLE_SWIFT_BIN` 이다**(두 스크립트 모두). 이걸 몰라서 이
  라운드의 초기 측정 전부가 6.2 였다 — CI 는 6.3.2 다.
- **공유 스크립트는 락이 빈 동안에만 고쳐라.** 동시 편집으로 bash 바이트 오프셋이 어긋나
