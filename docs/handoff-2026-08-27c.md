## 2. 세 번의 "문서가 틀렸다" — **이 라운드에서 가장 값진 산출**

시키는 대로 했으면 **없는 문제를 고치거나 있는 검증을 버렸을** 자리 셋이다.

### ① 캡처 갭 ②는 **과대평가**였다

`BACKLOG` 는 "오디오 반응 씬 스틸의 결정성 미보장 — 그 순간의 스펙트럼이 스틸에 구워진다"
고 적었다. **도달 불가다.** 사슬(줄 번호 전수 확인):

```
currentSpectrum 선언 초기값이 .silent                        SceneRenderer.swift:1385
setSpectrum* 밖에서 그 값을 쓰는 자리는 두 줄뿐              :2170 · :2178
그 둘은 if hasAudio, container.window != nil 안의 클로저 안  :2151
두 캡처 하네스 다 창 없는 오프스크린 뷰를 쓴다
```

**실효 게이트는 "창 유무" 하나**이고, 골든 하네스가 부르는 그 두 줄조차 헤드리스에서는
no-op 이다. 같은 항목 ①이 **과소평가**였던 것과 정반대 방향의 오차다.

### ② 재생목록은 **"데드 코드" 가 아니었다**

`PlaylistTransition.swift` 849행은 순수 값 타입·순수 함수이고 **테스트 참조가 48건** 있었다.
없던 것은 검증이 아니라 **소비자**다. "테스트 안 된 죽은 코드를 살린다" 로 접근했다면
이미 있는 오라클을 무시하고 다시 썼을 것이다.

### ③ 정점 포맷 플래그 — **질문 자체가 1바이트 오독 위에 있었다**

엔진은 매직을 `ReadCString` 으로 읽어 **NUL까지 9바이트를 소비**하는데 문서는 8바이트로 보고
`0x08` 부터 필드를 셌다. 그래서 논쟁하던 `0x0900`·`0x0f00`·`0x8000` 은 **실재한 적 없는
값**이다. 실제는 `0x09 u32 formatFlag / 0x0D u32 skinCount / 0x11 u32 meshCount`.

**교훈: 원장 항목을 읽을 때 서술을 사실로 받지 마라.** 셋 다 실측이 서술을 뒤집었다.

## 3. 판단이 필요했던 자리 셋

### `stop` — 축소 유지를 골랐다

결정적 사실은 **무엇이 실제로 `stop` 을 쏘는가**다. WE 기본값이 `playbacksleep = stop` 이고
`PlaybackEvaluator` 가 슬립 래치에서 진짜로 `stop: true` 를 낸다. 그러니 진짜 해제(teardown +
재마운트)는 **디스플레이 슬립마다 전 벽지 해제 + 깰 때마다 재마운트**가 된다 — 하루 수십 번,
`mount(in:project:)` 가 `throws` 인 경로에서. 깰 때 한 번 실패하면 **검은 데스크탑에 수동
재적용 말고 복구가 없고**, 재마운트 비용은 측정된 적이 없다.

축소가 잃는 것은 **메모리뿐, 그것도 화면이 꺼진 동안**이라 사용자에게 보이지 않는다.
산문으로 두지 않고 `stopIsReducedToPause` 상수 · `testWEDefaultStopIsDrivenByDisplaySleep`
(전제가 바뀌면 깨져서 결정을 다시 논하게 만든다) · **설정 화면 각주**로 남겼다.

### `supportsAudioProcessing` — (b) 의도적 미사용

재생성 코퍼스로 **WE 가 하드 게이트인 것은 확인했다**(`FUN_14006e0c0`). 그럼에도 (b)를 고른
이유는 RE 가 틀려서가 아니라 **이 코드베이스에서 (a)를 지금 하면 무슨 일이 나는가** 쪽이다:

WE 는 `SupportsAudioProcessing() && wproperties.audioprocessing.value` **두 항**을 접는데
둘째 항은 엔진이 합성 주입하는 유저 프로퍼티이고 Waple 에는 그것도 UI 도 없다. 선언만
배선하면 **사용자가 되돌릴 손잡이 없이 오디오가 꺼진다.** 게다가 이 리포의 어떤 게이트도 그
회귀를 못 본다 — 헤드리스 골든은 오디오를 통째로 꺼도 픽셀 diff 가 0 이다.

### 시각 전환 — 손대지 않았다

전환 효과 27종·`TransitionTimeline`·`transitionpool` 은 그대로 미소비다. GPU 도 데스크탑도
없어 **전환이 어떻게 보이는지 판정할 방법이 없다.** 같은 규율로 `PlaylistDriver` 에 만들었던
`shouldAdvanceOnVideoEnd` 를 **지웠다** — 소비자 없는 표면을 미리 만드는 것이 이 라운드가
고치고 있는 결함 자체다.
