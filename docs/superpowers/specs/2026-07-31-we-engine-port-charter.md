## 5. 검증 모델 — 픽셀 오라클은 존재하지 않는다

### 5-1. 확정된 제약

WE 프레임의 **결정적 캡처는 내재적으로 불가능하다.** 실행 검증 결과:

- 캡처 자체는 된다 — `-control openWallpaper -playInWindow -borderless` + Windows Graphics Capture.
  (데스크톱 모드는 `WS_EX_NOREDIRECTIONBITMAP` + `WS_CHILD` 로 3중 차단 — 배제.)
- 그러나 **시각 고정 수단이 바이너리에 없다.** `setTime`/`frameStep`/`freeze` 토큰 전무.
  클럭은 `QueryPerformanceCounter`, 유니폼은 `g_Time`/`g_Frametime`/**`g_Daytime`(실제 시각이 렌더 입력)**.
- `-control pause` 는 씬을 멈추지 못한다(실측: 8프레임 전부 다른 해시).
- 콜드오픈 3회 × 10프레임 → 해시 교집합 **0/10**.
- 코퍼스 162 씬 중 **158개**가 시간·오디오·파티클·스크립트 의존. 정적 후보 **3개(1.9%)**.

⇒ **"원본과 픽셀 동일"은 검증이 원리적으로 불가능하다.** 계약을 아래 3층으로 재정의한다.

### 5-2. 3층 검증 계약

| 층 | 무엇을 보장하나 | 방법 | Mac 필요 | CI |
| --- | --- | --- | --- | --- |
| **L1 의미론** | 구현이 정본과 일치 — 상수·수식·패킹·포맷 | `spec/` 대조 테스트(정본에서 생성) | ❌ | ✅ |
| **L2 지각 파리티** | 실코퍼스가 원본과 지각적으로 비슷 | 히스토그램·SSIM·에지·평균 luma | ✅ 코퍼스 필요 | ❌ |
| **L3 자기 회귀** | 변경이 의도한 것만 바꿈 | 커밋된 골든 대비 스냅샷 diff | ✅ 코퍼스 필요 | ❌ |

**L1 이 오라클을 대체한다.** 픽셀을 비교하는 대신 *WE 가 무엇을 하는지를 정본에 확정해두고 구현이
그대로 하는지*를 본다. **정본의 정확도가 곧 파리티의 상한이다.**

한계는 명시한다: 이 방식은 **정본에 적어둔 것만** 지킨다. 발견 못 한 것은 안 잡힌다. 그래서 전수 RE 가 전제다.

### 5-3. 텍스처 오라클 — **성립한다** (한 번 잘못 폐기했다가 복구)

`resourcecompiler64.exe -transcode` 로 `.tex` → RGBA8888 디코드가 된다.
**코퍼스 4,680 + 공유 311 텍스처 전체에 WE 자체 디코더 기준 골든이 가능하다.**

```
resourcecompiler64.exe -transcode -i <in.tex> -o <out.tex> -maxmipmaps 1
```

포맷별 실측:

| 입력 format | 결과 |
| --- | --- |
| **4 (BC3/DXT5)** · **6 (BC2)** · **7 (BC1)** | **→ format 0 RGBA8888 디코드** |
| 0 (raw) | 패딩 크롭만 (2048×2048 → 1920×1080) |
| 8 (RG88) · 9 (R8) | 바이트 동일 패스스루 — 대조 의미 없음 |

결정적이다(2회 실행 SHA 동일). 출력은 패딩이 크롭돼 `texW/texH` 가 `imgW/imgH` 로 갱신된다.

> ⚠️ **이 절은 한 번 틀렸었다.** 처음에 `.tex` 5표본으로 "디코더가 아니라 재압축기"라고
> **`확정`으로 기록하고 오라클을 폐기했다.** 표본 5개가 전부 패스스루 포맷(R8/RG88/raw)이라
> **디코드를 보여줄 수 없는 표본으로 부정을 결론낸 것**이다. BC 포맷으로 재검증해 반증했다.
>
> 교훈은 규약에 반영한다: **부정 결론(`X 는 되지 않는다`)은 긍정 결론보다 표본 설계가
> 중요하다.** 표본이 X 를 보여줄 수 있는 조건을 갖췄는지 먼저 확인해야 한다.
> `spec/README.md` 에 이 규칙을 명시했다.

함정 2건(대조 시 필수 반영):
①원본은 블록정렬 `texW×texH`, 실제 이미지는 `imgW×imgH` — 크롭 없이 비교하면 크기 불일치.
②레퍼런스의 mip1 이상은 크롭된 mip0 에서 **재생성된 것** → **mip0 만 정본으로 쓸 것**
(`-maxmipmaps 1` 로 mip0 단일 출력을 받는 게 적합).

**RePKG 등 제3자 구현은 오라클이 아니다** — Waple 과 같은 부류의 재구현이라 판정 기준이 못 된다.

### 5-4. 오라클이 없는 것 — 메시

`.mdl` 은 정본 생성 수단이 **없다.** `-mdl` 은 유효 OBJ 에도 무한 스핀, `.mdl → obj` 역변환 부재.
대신 **로제타석**을 쓴다 — §6.

## 6. 로제타석 — 소스와 컴파일 결과가 나란히 있다

`projects/defaultprojects/*/models/` 에 **`.obj`/`.mtl` ↔ `.mdl` 16쌍**이 같은 이름으로 존재한다.
OBJ 는 정점·UV 가 평문이고 MDL 은 그 컴파일 결과다. 손 디코드로 검증했다:

```
glow.obj  : 정점 4 · UV 4 · 쿼드 1 · 법선 없음, 첫 정점 x = -3.285059
glow.mdl  : "MDLV0004" | 00 | flag 0x09(pos+uv) | 1 | meshCount 1
            | "materials/audiophile/glow.json" 00 | 0 | 정점블롭 80B(=4×20B)
            | 68 3E 52 C0 = float -3.28506   ← 일치
```

**`.mdl` 파서를 바이트 단위로 검증할 수 있다.** AABB 부재도 `hasAABB = version >= 17` 규칙과 정합.

`.tex-json` **388개**도 같은 성격이다 — `{"format":"rgba8888","nomip":true,"nonpoweroftwo":true,"clampuvs":true}`
같은 **tex 컴파일 파라미터의 정본**.

**규약 3개:**
1. 모든 항목에 **근거 필드 필수**. 근거 없는 항목은 `status: "추정"` 이고 **테스트를 생성하지 않는다.**
2. 정본에서 **골든 테스트를 자동 생성**한다. 사람이 손으로 쓰지 않는다.
3. `spec/` 에는 **원문이 아니라 파생 사실**(값·표·필드 정의)을 담는다.
   `spec/evidence/` 는 주소·수치·짧은 발췌만.

> 규약 3 의 이유는 **저작권이 아니라 기계 검증 가능성**이다. WE 에셋은 `assets/` 에 원문 그대로
> 동봉된다(§11 — 사용자의 라이선스 판단). 정본이 원문 사본이면 테스트를 생성할 수 없고 diff 도
> 의미가 없다. 정본은 "무엇이 참인가"의 구조화된 기록이어야 한다.
> 전체 디컴파일 덤프를 넣지 않는 것도 같은 이유다 — 6,843개 함수 덤프는 검증 가능한 사실이 아니다.

## 8. 검토 후 철회한 안

**D3D11 참조 렌더러(Windows)** — 초기에 채택했다가 조사 결과로 철회.

1. **참조 렌더러는 오라클이 아니다.** 내가 쓴 렌더러가 Waple 과 다르면 어느 쪽이 틀렸는지 모른다.
   판정 기준은 WE 여야 한다.
2. **정적 판독이 이미 같은 답을 냈다.** 렌더러 없이 블렌드 32식 1:1 대조, 라이트 패킹 확정,
   falloff 두 레인 발견, GGX 이탈·앰비언트 이탈 적발, `g_TexelSize` 판별 — **비용 사실상 0.**
3. **Swift 에 D3D11 바인딩이 없다.** `swift-com` 전수 확인 결과 D3D11 인터페이스 0건(D3D12/DXGI 전용).
   대안 프로젝트는 2021년 정지. Swift COM interop 은 2026-04 제안 단계.
4. **셰이더 층 이중화.** `GLSLTranslator.swift` 1,973줄은 MSL 전용. D3D11 을 택하면 GLSL→HLSL
   방출기가 필연이고 **Metal 이식 시 재사용 0**.

**픽셀 캡처 오라클** — §5-1 근거로 철회.

| **scene** (162) | 렌더러 문제. 어려운 부분은 GPU 가 아니라 **의미론**이고 대부분 평문으로 확보됨 |

## 12. 미해결 — 사람 결정 또는 추가 조사

**결정 필요:**
- Waple 의 의도적 이탈을 유지할지 제거할지 — GGX 분모 바닥값 `1e-4`, `nl>0` 조기반환,
  블렌드 엡실론 가드. **[0,1] 입력에선 등가, HDR >1 / 음수에서만 갈린다.**
- falloff 레인 — Waple 은 HLSL 레인 채택. GLSL 레인은 `falloff < 6.1e-5` 를 강제 0으로.
  반경 경계와 `exponent=0` 에서 갈린다.

**조사 필요(P0):**
- `combine_hdr` 의 `#if LINEAR == 1` 이 백버퍼 포맷과 어떻게 대응하는가.
  Waple 현행 규약이 자기정합적이라는 건 검증이 아니다 — 체계적 감마 오차는 안에서 보면 그렇게 보인다.
- `g_LightAmbientColor` 흰색 폴백의 **실제 블라스트 반경** — 워크샵 셰이더 선언 0건이라
  베이스 에셋 `genericimage4` 번역 경로를 타는 씬 수를 세야 한다.
- 패스 스케줄러 순서 — `ccsimple` 이 블룸 전/후, MSAA resolve 위치, 밉 생성 시점.

**조사 필요(P1):** `g_BloomBlendParams` 유도식 · HDR 프레임버퍼 실제 포맷 ·
`g_Daytime`/`g_bufStatic`/`g_LayerModelMatrix` 레이아웃 · `shaders/declarations.json` 정체 ·
