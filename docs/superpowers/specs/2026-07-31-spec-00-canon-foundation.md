# 스펙 0 — 정본 기반 구축 (선행 기반)

**작성 2026-07-31.** 차터: [2026-07-31-we-engine-port-charter.md](2026-07-31-we-engine-port-charter.md)

> **이 스펙은 목표가 아니라 선행 기반이다.** 이 프로그램의 산출물은 `WapleEngine` 재구현이고,
> 그건 스펙 2 다(차터 §9). 여기서는 엔진을 짓기 **전에** 갖춰야 하는 것 — 정본 체계, 에셋 동봉,
> 그리고 `정본 → 테스트 → 검증` 루프가 실제로 도는지의 확인 — 만 한다.
>
> 대상을 **기존 `WapleRender`** 로 잡은 것은 그것을 개선하는 게 목적이어서가 아니라,
> **루프를 엔진 전체에 걸기 전에 작은 것으로 시험**하기 위해서다. 여기서 얻는 교정
> (에셋 결손 해소·이탈 3건)은 부수 이득이고, 검증된 정본과 루프가 스펙 2 로 그대로 넘어간다.

## 1. 이 스펙이 끝나면 무엇이 달라지나

1. `spec/` 이 생기고, 지금까지 확보한 정본이 **기계 판독 가능한 형태**로 착지한다.
2. `assets/` 가 동봉되어 **씬 배경이 WE 설치 없이 돈다**(현재 약 86%가 공유 에셋 결손).
3. 정본 대조로 확인된 **이탈 3건이 교정**된다.
4. `spec → 테스트 생성 → CI 검증` 루프가 한 바퀴 돌아, 이 방식이 작동하는지 알게 된다.
5. **L3(스냅샷 회귀) 골든이 커밋되어** 이후 작업의 안전망이 실제로 존재하게 된다(§8-2).

## 3. `spec/` 개설

리포 루트 `spec/`. 이 스펙에서는 **지금 확보된 것만** 채운다. 나머지는 후속 스펙이 추가한다.

```
spec/
  README.md              규약 — 근거 필수, 생성 대상, evidence 정책
  uniforms.json          g_* 143종
  formats/tex.json       TEXV/TEXI/TEXB/TEXS 필드 정의
  formats/mdl.json       MDLV 버전별 레이아웃
  formats/pkg.json       PKGV 컨테이너
  shaders/headers.json   common_*.h 6종 — 의미론과 소비처
  corpus/inventory.json  446종 실측 도수(버전·포맷·키 분포)
  evidence/              주소·짧은 발췌·바이트 덤프
```

### 3-1. 항목 스키마

모든 항목은 이 형태를 따른다:

```json
{
  "id": "uniform.g_LightAmbientColor",
  "value": "...",
  "status": "확정" | "추정",
  "evidence": [
    { "kind": "shader",  "ref": "assets/shaders/genericimage4.frag:140" },
    { "kind": "corpus",  "ref": "ambientcolor 0.3×113 / 0×31 / 1×5 (162 pkg)" },
    { "kind": "binary",  "ref": "wallpaper64.exe@0x486898" }
  ]
}
```

**`status: "추정"` 인 항목은 테스트를 생성하지 않는다.** 근거 없는 값이 골든이 되면 그 순간
정본이 오염된다.

### 3-2. evidence 정책

`spec/evidence/` 에는 **주소·수치·짧은 발췌만** 넣는다. 전체 디컴파일 덤프나 WE 셰이더 원문 전사는
넣지 않는다 — 정본은 *무엇이 참인지*의 기록이지 원본의 사본이 아니다.

### 4-2. 어디에

`Sources/WapleRender/Resources/WEAssets/` — SwiftPM `.copy` 리소스. 앱 번들에 그대로 들어간다.

### 4-3. 해석 순서 (기존 계약 유지)

`BaseAssetsSettings` 의 3단 폴백을 **4단으로 확장**한다:

```
1. 패키지 안 (scene.pkg)                       ← 배경 전용
2. 사용자 지정 경로 (waple.baseAssetsPath)      ← 기존
3. 자동 탐지 경로 (~/Downloads/... )            ← 기존
4. 앱 동봉 WEAssets/                            ← 신설
```

동봉본을 **마지막**에 두는 이유: 사용자가 최신/수정된 WE 설치를 갖고 있으면 그쪽이 이긴다.
동봉본은 "없을 때의 바닥"이다.

### 4-4. 검증

- `assets/` 동봉 전후로 **공유 에셋 결손 로그 건수**를 센다. 정찰 추정으로 씬의 **약 86%** 가
  공유 `.tex` 를 최소 1개 요구한다(정찰 분모 161 vs 본 세션 실측 162 — 분모가 달라 비율만 쓴다).
  실제 결손 건수는 이 스펙에서 **직접 측정**하고, 목표는 **0건**이다.
- `NOTICE` 에 WE 에셋 동봉 사실과 출처(2.8.42)를 기재. `assets/fonts` 의 SIL OFL·RobotoMono
  라이선스 파일은 **함께 동봉**한다(원 라이선스가 요구).

> ⚠️ **동봉본은 WE 2.8.42 에 묶인다.** WE 업데이트가 에셋을 바꾸면 조용히 낡는다.
> `spec/` 매니페스트에 **WE 버전과 파일 해시**를 기록해 드리프트를 감지 가능하게 한다.

## 5. 텍스처 골든 오라클 — **성립한다** (한 번 잘못 폐기했다가 복구)

이 절은 한 번 "전제가 반증됐다"며 오라클을 범위 밖으로 뺐었다. **그 판단이 틀렸다.**
표본 5개가 전부 패스스루 포맷이라 디코드를 보여줄 수 없었을 뿐이다(경위는 charter §5-3).

### 5-1. 생성 (Windows)

```
resourcecompiler64.exe -transcode -i <in.tex> -o <out.tex> -maxmipmaps 1
```

BC1/BC2/BC3(format 7/6/4) → **RGBA8888(format 0) 디코드**. 결정적(2회 실행 SHA 동일).
format 8(RG88)·9(R8)은 패스스루라 대조 대상이 아니고, format 0(raw)은 패딩 크롭만 된다.

대상: 코퍼스 `.tex` **4,680개** + 공유 `.tex` **311개**.
그중 실제 대조 가치가 있는 것은 **BC 계열**이다 — 코퍼스 실측 분포로 대상 수를 확정할 것.

### 5-2. 함정 2건 (필수 반영)

1. **크기 불일치** — 원본은 블록정렬 `texW×texH`, 실제 이미지는 `imgW×imgH`.
   출력은 크롭돼 나오므로 **원본 쪽을 `imgW×imgH` 로 크롭한 뒤** 비교한다.
2. **mip1 이상은 재생성본** — 레퍼런스의 mip1+ 는 크롭된 mip0 에서 다시 만든 것이다.
   **mip0 만 정본으로 쓴다.** `-maxmipmaps 1` 로 mip0 단일 출력을 받는 게 적합하다.

### 5-3. 산출물

`spec/golden/tex/` 에 (원본 해시 → 디코드 결과 해시 + 크기 + 포맷) 매니페스트.
**PNG 전량을 커밋하지 않는다** — 해시와 소수의 대표 샘플만. 전량은 Windows 에서 재생성 가능.

### 5-4. 소비

`Tests/WapleRenderTests` 에 생성 테스트: 코퍼스가 있으면 전량 대조, 없으면 동봉 샘플만.
**CI 에서도 동봉 샘플분은 돈다** — 현재 `TexDecoderTests` 가 합성 픽스처에만 의존하는 것보다 강하다.

## 6. 확정 이탈 교정 3건

정본 대조로 확인됐고 소스에서 실재를 확인했다.

### 6-1. `g_LightAmbientColor` 흰색 폴백

**현재** `Sources/WapleCore/GLSLTranslator.swift:1257`
```swift
if name == "g_LightAmbientColor" { return "float4(1.0, 1.0, 1.0, 1.0)" }
```
주석이 스스로 *"실제 scene ambientColor 연동 전 흰색 중립값"* 이라고 적어둔 임시값이다.

**정본** 씬 기본값은 **0.3** (코퍼스 실측: `ambientcolor "0.3 0.3 0.3"` 113 / `"0 0 0"` 31 / `"1 1 1"` 5,
`skylightcolor "0.3 0.3 0.3"` 152). 즉 현재 **3.33× 과대**.
모델 경로는 평면값이 아니라 **반구 보간**: `mix(g_LightSkylightColor, g_LightAmbientColor, dot(N, up)*0.5+0.5)`
(`generic4.vert:168`, `base/model_vertex_v1.h:209`). 2D 이미지 레이어만 평면
`g_LightAmbientColor * color.rgb` (`genericimage4.frag:140`).

**조치** 상수 주입을 제거하고 **씬 `ambientcolor`/`skylightcolor` 를 실제로 배선**한다.

> ⚠️ **블라스트 반경 미측정.** 워크샵 셰이더 중 `g_LightAmbientColor` 선언은 **0건**이다.
> 이 폴백이 발화하는 건 베이스 에셋 `genericimage4`/`fluidsim` 을 번역해 쓰는 경로뿐이다.
> **선행 작업:** 그 경로를 타는 씬 수를 로그로 세고, 1.0 → 0.3 변경 전후 A/B 캡처.
> 반경이 0이면 값만 고치고 넘어가고, 크면 별도 검증 라운드를 붙인다.

### 6-2. `g_TextureNResolution` 4성분 실전달

**현재** `Sources/WapleRender/SceneRendererFrameEncoder.swift:74`
```swift
texRes[slot] = SIMD4(w, h, w, h)
```

**정본** `(할당폭, 할당높이, 실이미지폭, 실이미지높이)`. `.zw/.xy` 비율이 **NPOT 패딩 보정 UV 스케일**이다.

**영향 규모** `*Resolution` 참조 셰이더 324개 중 **194개(60%)** 가 `.z/.w` 를 쓴다.
pkg 기준으로는 **150/162(93%)**. 소수 예외가 아니다.

**조치** 실제 4성분을 싣는다. Waple 이 텍스처를 크롭 업로드하는 한 현행이 자기정합적이지만
**`keepFullAtlas` 스프라이트 아틀라스에서 불변식이 깨진다.**

### 6-3. GGX 분모 바닥값

**현재** `Sources/WapleRender/Mesh3DShaders.swift:171` `max(rawDenominator, 1e-4)` ·
`Sources/WapleCore/ScenePBRLighting.swift:7` `ggxDenominatorFloor = 1e-4`

**정본** WE 원문에 바닥값이 **없다**: `return rSqr2 / (M_PI * denominator * denominator);`

**조치** — **이건 결정이 필요하다.** [0,1] 입력에선 등가고 **HDR >1 / 음수 입력에서만 갈린다.**
같은 성격의 이탈이 둘 더 있다(`nl>0` 조기반환, 블렌드 엡실론 가드 — WE 는 정확 비교
`blend==0.0`/`==1.0`, Waple 은 step/select + 1e-5).
**세 건을 묶어 "안전장치로 유지" 인지 "정본 일치로 제거" 인지 한 번에 정하고 `spec/` 에 명시한다.**
그래야 나중에 재발굴되지 않는다.

## 8. 검증

### 8-1. 무엇을 어디서

| 무엇 | 어떻게 | Mac | CI |
| --- | --- | --- | --- |
| `spec/` 스키마 유효성 | 스키마 검사 + 근거 필드 존재 | ❌ | ✅ |
| `spec/` 정본 ↔ 구현 상수 일치 | 정본에서 생성된 유닛 | ❌ | ✅ |
| 에셋 결손 0건 | 마운트 로그 카운트 | ✅ | ❌ |
| 이탈 3건 교정 | 정본 대조 유닛 | ❌ | ✅ |
| 무회귀(유닛) | 기존 2,125 테스트 | ❌ | ✅ |
| 무회귀(픽셀) | 씬 170종 스냅샷 | ✅ 코퍼스 필요 | ❌ |

**테스트 수 기준값 2,125 는 증가한다.** AGENTS.md 의 "리팩토링으로 이 숫자가 변하면 잘못됐다" 는
리팩토링 기준이고, 이 스펙은 신규 테스트를 추가하므로 해당하지 않는다. **새 기준값을 AGENTS.md 에 갱신한다.**

### 8-2. ⚠️ L3(픽셀 회귀)은 현재 사실상 비어 있다 — 이 스펙에서 채운다

`assets/` 동봉과 이탈 교정은 **모든 씬의 픽셀을 바꾼다.** 그 안전망이 L3 인데, 지금 상태로는
안전망이 아니다:

- **F402/F403** — `git ls-files` 상 **커밋된 골든 0건.** luma 기준선이 처분성 `/tmp/waple_gt` 에
  저장되고 드리프트는 `NSLog` 경고뿐. 하드 오라클은 **"마운트 무크래시 + PNG 존재"** 라서
  **완전 검정 프레임도 통과한다.**
- **F144** — `SnapshotCompare` 의 결정/비결정 임계가 베이스라인 캡처 시점 1회 기록에 영구 고정.
  결정적이던 씬이 비결정이 되어도 신호 없음.
- 벽시계 오염 — JS `Date` 미스텁이라 시계 텍스트 씬의 diff 에 캡처 시각차가 섞이고,
  같은-분 셀프체크가 "결정"으로 오분류된다.

**따라서 §10 순서에서 골든 커밋이 `assets/` 동봉보다 먼저다.** 변경 전 기준선을 확보하지 않으면
"바뀐 것이 의도한 것인지"를 판정할 방법이 아예 없다.

| 위험 | 완화 |
| --- | --- |
| **L3 가 지금 아무것도 못 잡는다**(§8-2) | **골든 커밋을 변경보다 먼저** 한다(§10 1~2단계) |
