# RE 방법론 — 실제로 당한 함정 27개와 검증 규율

Waple 은 Wallpaper Engine(WE)의 동작을 **실측으로** 재현하는 리포다. 사실의 출처는 셋뿐이다:

1. **자산** — WE 설치본과 동봉 `Sources/WapleRender/Resources/WEAssets/`(설치본 `assets/` 와 바이트 동일)의 GLSL·json·`.tex`·`.mdl`
2. **바이너리** — `wallpaper64.exe`(imagebase `0x140000000`) 외 여러 개
3. **로제타석** — 같은 원본의 구운 짝(`.obj`↔`.mdl` 등) 바이트 대조

이 문서는 그 셋을 다루면서 **실제로 틀렸던** 방식만 모은 것이다. 하나하나가 이 리포에서
잘못된 코드나 잘못된 정본을 낳았고, 그 자리를 고치면서 적었다. 추측으로 적은 항목은 없다.

> **왜 리포에 있나.** 종전에는 이 목록이 세션 스크래치패드에만 있었다. 컨테이너는 휘발성이라
> 새 세션이 시작될 때마다 같은 함정을 처음부터 다시 밟았다. 실제로 여러 항목이 **두 번 이상**
> 당한 것이다(16·17·21). 리포에 두면 다음 사람이 안 밟는다.

---

## 0. 절대 규칙

1. **모르면 "모른다"고 써라.** 추정을 확정처럼 쓰면 그게 최악의 결과물이다 — 틀린 코드보다
   나쁘다. 틀린 코드는 테스트가 잡지만 틀린 확정은 다음 사람이 근거로 삼는다.
   문장마다 **확정 / 추정 / 미해결** 을 구분해라. 이 리포의 정본(`spec/**/*.json`)은
   `status` 필드로 그것을 강제한다.
2. **도수에는 범위 라벨을 붙여라.** "4건" 은 사실이 아니다. "동봉 355 씬 중 4건" 이 사실이다.
   측정 안 한 코퍼스는 **0 이 아니라 미측정**이다.
3. **정본을 줄이지 마라.** `specfmt.dump` 의 축소 가드(키 소실 = 에러)를
   `allow_shrink` / `WAPLE_SPEC_ALLOW_SHRINK=1` 로 끄지 마라 — 가드를 영구히 무력화한다.
   옛 키를 남기고 `해소`/`closed` 를 추가하는 **툼스톤 규약**을 써라.

## 1. 바이너리를 뜯을 때

### 1. `.pdata` 조각 ≠ 함수
언와인드 정보는 한 함수를 여러 조각으로 쪼갠다. 조각 하나를 함수로 착각하면 범위가 잘린다.
조각을 병합한 실제 범위를 잡고 시작해라.

### 2. 한 요소에 핸들러가 **둘** 붙을 수 있다
"이 키의 핸들러를 찾았다" 는 "이 키의 핸들러를 **다** 찾았다" 가 아니다.

### 3. 주입 ≠ 소비
파서가 기본값을 DOM 에 심는 것(`Json::Value::find` `0x140087490`)과, 그 값이 실제로 멤버에
착지하는 것은 **다른 사건**이다. 착지는 리플렉션 바인더
(`H_FLOAT 0x1401d7d30` / `H_INT 0x1401d7be0` / `H_STRING 0x1401d7e80` / `H_BOOL 0x1401d8120`)
나 직독(`asFloat 0x140086220` / `asInt 0x140085ee0` / `asUInt 0x140085f70` / `asBool 0x140086300` /
`asString 0x140085cc0`)
으로 일어난다. **후자만 소비다.** 주입만 보고 "이 키가 쓰인다" 고 적으면 틀린다.

### 4. 호출 사이트가 아니라 **상수 적재 횟수**를 세라
"이 상수를 쓰는 곳이 몇 군데냐" 를 함수 호출 수로 세면 틀린다. 즉치(immediate)가 이미지
어디에 몇 번 박혀 있는지를 세라. 인라인된 사본이 호출보다 훨씬 많다
(실사례: `isNumeric` 게이트 93자리 중 `call` 은 12, 나머지 81 은 인라인이었다).

### 5. 레지스터 상수는 **지배관계**로 판정해라
`r10d` 가 이 시점에 무엇인지는 "가장 가까운 대입" 이 아니라 **지배하는 대입**이 정한다.
루프 back-edge 에서 되돌려 놓는 대입을 놓치면 값이 뒤집힌다.

### 6. **x86 을 뜯기 전에 자산을 먼저 grep 해라**
이 리포에서 가장 자주 시간을 아낀 규칙이다. 답이 **셰이더 소스에 그냥 적혀 있는** 경우가 많다.
실사례: `.mdl` 정점 플래그 `0x20`(`a_TexCoordVec4`)의 `.zw` 가 두 번째 UV 세트라는 것은
`generic.vert` 의 `#if LIGHTMAP` 과 `generic.frag` 의
`texSample2D(g_LightmapMapSampler, v_TexCoord.zw)` 가 그대로 적고 있었다.

### 7. 파서가 **실제로 읽는** 키를 확인해라
비슷한 이름의 형제 키에 속는다. json 에 적힌 이름과 코드가 읽는 이름이 다를 수 있다.

### 8. ASCII 와 **UTF-16LE 를 둘 다** 검색해라
한쪽만 보면 0건이 나온다.

### 9. 15바이트 이하 짧은 문자열은 `lea` 가 아니라 `mov` 로 온다
MSVC 의 SSO(작은 문자열 최적화) 때문이다. `lea` 선형 스캔은 **0건**을 준다.
이미지 전체 바이트 스캔으로 disp32 xref 를 떠라.

### 10. rip-상대 xref 스캔은 **disp32 에 RVA 가 박힌** 주소지정을 놓친다
`[r11 + rax*4 + 0x484a20]` 같은 형태다. 베이스+인덱스+disp32 는 rip-상대가 아니므로
rip 스캔에 안 걸린다. 병렬 배열은 대개 이 형태로 읽힌다.

### 11. **바이너리 하나 ≠ WE**
WE 는 여러 실행 파일/DLL 로 나뉜다 — `wallpaper64.exe`, `webwallpaper64.exe`,
`scenescript64.dll`, `resourceutil64.dll`, `cloneextensions64.dll`, `wallpaperui.exe`,
`mediaextensions64.dll`(OpenAL 오디오), `winrtutil64.exe`, `resourcecompiler64.exe`.
한 파일에서 못 찾았다고 없는 게 아니다. **어느 바이너리에서 뜬 것인지 항상 명시해라.**

### 12. 행/열 주도는 **레이아웃만으로 판정 불가**
D3D 행벡터/행주도와 GL 열벡터/열주도는 같은 변환에 대해 **바이트 동일**하다.
같은 4×4 를 basis + translation 으로 **쪼개는** 지점을 찾아야 갈린다
(`Matrix::block(3)` `0x14005f600`). 규약은 **값**으로 판정해라 — 알려진 회전을 넣어 결과를 봐라.

### 13. "저장을 건너뛰는" 실패 분기는 **생성자 기본값**을 남긴다
false 가 아니다. 태그 검사 게이트를 무지성으로 붙이면 **기본값이 true 인 키가 뒤집힌다.**

### 14. 남의 주석에 적힌 **함수 범위·VA 를 베끼지 마라**
디스크립터 테이블은 *다음* 항목의 이름 `lea` 를 *현재* 항목의 스토어 사이에 끼워넣기 때문에,
순진하게 덤프하면 한 칸씩 밀린다. 이 세션에만 이런 오류가 여러 건 나왔다. **직접 다시 떠라.**

### 15. **거꾸로 디스어셈하면 어긋난다**
후보 주소에서 거슬러 올라가며 뜨면 명령 경계가 밀려 **없는 명령이 보인다.**
반드시 `.pdata` 함수 시작에서 **선형으로** 내려와라.
- 실사례 A: `0x1401a9056` — 태그 로드와 `dec` 사이의 `mov r13d, 1` 을 역방향 디스어셈이 통째로 놓쳤다.
- 실사례 B: `0x140262330` 에서 시작하면 `lea eax, [rdi+0x1c4]` 로 보이지만, 실제 경계는  [VA-정정]
  `0x14026232f` 의 `lea r8, [r15+0x1c4]` 다. 한 바이트 차이로 **다른 레지스터**가 된다.

### 16. **유니폼 슬롯 상수를 이름 `lea` 옆에서 읽으면 한 칸 밀린다**
등록 함수가 이름 문자열과 슬롯 id 를 나란히 놓는 것처럼 보여도 그 짝이 맞다는 보장이 없다.
실사례: `g_TextureNRotation` 옆의 `mov …, 0x29` 는 사실 `g_Texture9` 의 것이었다.
→ 슬롯은 **업로더 점프 테이블에서 되짚어** 확정해라(어느 암이 어느 씬 오프셋을 쓰는지).

### 16b. **xref 스캔이 주는 주소는 명령 주소가 아니라 `disp32` 필드 위치다**
`lea r8, [rip + d]` 를 바이트 스캔으로 찾으면 나오는 것은 **`d` 가 박힌 자리**다. 그걸 그대로
인용하면 명령 주소보다 정확히 3바이트(인코딩에 따라 2~4) 뒤를 가리킨다 — 읽는 사람이 거기서
디스어셈하면 함정 15 를 그대로 밟는다. 이 리포의 문서에서 실제로 31건이 그 상태였다.
→ 인용 전에 `scripts/re/va_citations.py` 로 **전수 대조**해라. 어긋난 인용마다 어느 명령의
   몇 바이트 안인지, `disp32` 위치인지까지 찍고 원래 명령 주소를 제시한다.

### 16c. **디컴파일 창의 주소는 원본 주소가 아니다 — Ghidra 산출물은 +0xD0 밀려 있다**
이 리포가 쓴 Ghidra 매핑은 rich header 가 주입된 이미지라 **원본보다 208바이트(0xD0) 크다.**
그래서 `FUN_140261950` 의 원본은 `0x140261880` 이다(`spec/engine/decompilation-provenance.json`).
디컴파일 창의 주소를 그대로 "어셈블리 0x…" 로 옮겨 적으면 **전부 밀린 주소**가 된다.

2026-08-21 전수 스윕 실측: 경계를 벗어난 인용 중 **79개가 이 부류**였다.
`Sources/WapleCore/Model3D.swift` 는 검출된 8건이 **전부** 주입본이었고 — 같은 파일의 메시
프레이밍 절 주소는 원본이 맞았다. 즉 **한 파일 안에 두 주소공간이 섞여** 있었다. 결정적 대조:
그 파일이 `0x140261ca7` 을 `cmp edi,0x17`(v≥23 게이트)이라고 적었는데 원본 이미지의 그 주소는  [VA-정정]
`mov r12d,[rdi]` 이고, `0x140261bd7`(=−0xD0)이 정확히 `cmp edi,0x17` 이다.

→ `scripts/re/va_citations.py` 가 `va − 0xD0` 도 자동으로 재서 `주입본 주소(Ghidra, +0xD0)` 로
   분류하고 원본 주소를 제시한다. **규약은 원본 주소다** — Ghidra 이름(`FUN_…`)을 남기고 싶으면
   원본 주소를 함께 적어라.
→ 두 가설(`disp32` 위치 · 주입본)이 동시에 성립할 수 있다. `disp32` 는 **어긋난 바이트 수까지**
   설명하므로 그쪽이 이긴다. 실사례 `0x14015cc13`: `-0xD0`도 경계지만 그 자리는 무관한 `jne`  [VA-정정]
   이고, 원문 주장(`"condition"` 로드)과 맞는 것은 `0x14015cc10` 의 `lea r8, [rip+…]` 다.

### 17. **불리언은 숫자다**
jsoncpp `asFloat`(`0x140086220`) · `asInt`(`0x140085ee0`) · `asUInt`(`0x140085f70`) ·
`asInt64`(`0x1400860c0`) · `asUInt64`(`0x140086000`) 는
**태그 5(boolean)를 1/0 으로 받는다.** 좁히는 것은 호출부의 `isNumeric`(`0x140088880`) 게이트뿐이고,
그런 자리는 전체 90곳이다(`asFloat` 호출 243 · `asUInt` 79 중 — 옛 문면의 "asInt 79" 는
**이름이 바뀐 값**이었다, 아래 함정 27). 파티클 디스패처는 229곳 중 6곳만
게이트한다. **전역 엄격화 금지** — 223자리가 회귀한다.
관용도 사다리는 `numeric* ⊂ strict* ⊂ lenient*`(`Sources/WapleCore/JSONNumerics.swift`).

## 2. 정본(`spec/**/*.json`)을 다룰 때

### 18. 이 컨테이너에서는 정본을 **재생성할 수 없다**
`scripts/spec/measure_*.py` 는 `WE_ROOT` 와 `WE_WORKSHOP` 을 요구하는데 **워크샵 코퍼스가 없다**.
`WE_ROOT` 만 줘도 코퍼스를 읽는 측정기는 `FileNotFoundError` 로 죽는다 — 그게 **옳은 동작**이다
(0건을 확정으로 찍는 것보다 낫다. `scripts/spec/check_spec_shrink_guard.py` 머리말 참조).
현재 이 환경에서 도는 측정기는 36개 중 **14개**이고, 그 14개는 고정점이다(돌려도 정본이 안 바뀐다).

→ 그래서 정본은 **손으로 고치되 생성기 리터럴과 반드시 함께** 고쳐야 한다.
→ 그리고 **재현 못 한 수치를 정본에 새로 쓰지 마라.** 코퍼스 있는 환경에서 재생성하면
   들어올 델타를 생성기 주석에 적어 두는 것이 이 리포의 관례다.

### 19. 구현만 고치면 **정본이 낡아 다음 사람이 되돌린다**
`Sources/` 를 고쳐 사실을 바꿨으면 `spec/**/*.json` 과 `scripts/spec/measure_*.py` 를
**둘 다** grep 해서 같은 사실이 적힌 자리를 전부 고쳐라.
`check_canon_generator_keys.py` 는 **키만** 잡고 값은 안 잡는다 — 낡은 값은 조용히 산다.
실사례: `ca5def6` 이 `.mdl` 정점 표를 11→26엔트리로 고쳤는데 정본은 11엔트리인 채였다.

### 20. 정본은 **자기 자신과 모순될 수 있다**
같은 파일의 두 엔트리가 갈린 채 오래 산다. 실사례: `spec/formats/mdl-deep.json` 의
`format.mdl.meshLayout` 이 인덱스를 "u16" 고정으로 적는 동안, 같은 파일의
`format.mdl.indexWidth` 는 "폭 = 2 + 2\*(gateWord & 1)" 라고 적고 있었다.
→ 정본에 새 사실을 넣을 때는 **같은 파일 안에서 그 사실의 키워드를 grep** 해서 모순을 찾아라.

### 21. 정본을 손으로 고칠 때의 안전한 절차
생성기의 **리터럴 키만** 뽑아 정본에 반영하고 코퍼스 유래 값은 손대지 마라.
반드시 `specfmt.dump` 를 통해 써서 축소 가드를 통과시켜라.

### 22. **줄 번호로 건 예외·인용은 무관한 편집을 막고 조용히 낡는다**
`check_spec_shrink_guard.py` 의 `RAW_DUMP_ALLOWED` 가 `(파일, 줄번호)` 였다가 실제로 그 사고를
냈다(`94045ac` 에서 **전문 일치**로 교체). 마찬가지로 주석·문서에서 **다른 파일의 줄 번호를
인용하지 마라** — 한 줄만 밀려도 엉뚱한 곳을 가리킨다. 그 줄의 **코드를 적어라.**

### 27. **함수에 붙인 이름은 근거가 아니다 — 이름을 바꿔 달면 온 리포가 같이 틀린다**

이 리포는 jsoncpp 접근자 두 쌍의 이름을 **서로 바꿔** 달고 있었고, 그 오기가 18자리로 번져
있었다(`Sources` 7 · `Tests` 3 · `docs` 8). VA 는 전부 맞았다 — **틀린 것은 라벨뿐**이다.

판정은 추측이 아니라 실패 경로의 `_wassert` 인자다. 각 함수는 실패할 때
`_wassert(식, L"D:\dev\we\windows\src\json\src\json_value.cpp"(`0x140478640`), 줄)` 을
부르는데, 그 **문자열과 줄 번호가 원본 jsoncpp 의 함수 순서와 정확히 맞는다**:

| VA | 실패 문자열 | 줄 | 이름 |
| --- | --- | ---: | --- |
| `0x140085cc0` | "Type is not convertible to string" | 696 | `asString` |
| `0x140085ee0` | "Value is not convertible to Int." | 719 | **`asInt`** |
| `0x140085f70` | "Value is not convertible to UInt." | 741 | **`asUInt`** |
| `0x1400860c0` | "Value is not convertible to Int64." | 769 | **`asInt64`** |
| `0x140086000` | "Value is not convertible to UInt64." | 790 | **`asUInt64`** |
| `0x140086150` | "Value is not convertible to double." | 829 | `asDouble` |
| `0x140086220` | "Value is not convertible to float." | 852 | `asFloat` |
| `0x140086300` | "Value is not convertible to bool." | 873 | `asBool` |

변환 관용구도 같은 방향으로 갈린다 — `0x140085ee0` 의 태그 3 은 `cvttsd2si eax`(**32비트**,
`0x140085f12`)이고 `0x140085f70` 의 태그 3 은 `cvttsd2si rax`(**64비트**, `0x140085fa2`) 뒤
`eax` 반환이다. MSVC 가 `int(double)` 과 `unsigned(double)` 를 내리는 방식 그대로다.

**그래서 규칙**: 함수 이름을 문서에 적을 때는 **그 이름을 어떻게 알았는지**를 같이 적어라
(문자열·어서션·export·RTTI·호출 규약 중 무엇인가). 이름만 적힌 인용은 다음 사람이 검증할
수 없고, 틀렸을 때 **VA 가 맞아서 아무 검사기도 못 잡는다** — `va_citations.py` 는 주소가
경계인지만 본다. 산문이 이름에 기대 결론을 내렸으면(부호 유무·폭) 그 결론까지 같이 무너진다.

## 3. Swift·CI 쪽

### 23. **리눅스 초록이 macOS 초록이 아니다 — Foundation 구현이 다르다**
개발 컨테이너는 swift-corelibs-foundation, CI 는 Apple Foundation 이다. 실측 사례:
`JSONSerialization` 의 **중복 키 승자**가 갈린다 — `{"a":1,"a":2}` 가 리눅스에서 `2`(뒤가
이긴다, WE 와 같다), macOS 에서 **`1`**(앞이 이긴다). 이것 때문에 리눅스 테스트가 초록인 채로
macOS CI 가 붉었다(`AssetJSONLenientTests` 2건).
→ Foundation 파스에 **직접 기대는** 코드를 고칠 때는 리눅스 초록을 근거로 삼지 마라.
   플랫폼이 갈리면 `#if canImport(Darwin)` 로 **양쪽 실측값을 각각** 단언해라.

### 24. Swift 문자 클러스터: `Character("\r\n") != "\n"`
CRLF 가 섞인 입력에서 `split(separator: "\n")` 이 조용히 다르게 동작한다.

### 25. `XCTAssertEqual` 은 `Equatable` 을 요구한다
리눅스 심에 enum 을 추가할 때 반복해서 걸렸다(`MTLCommandBufferStatus` ·
`AVPlayer.TimeControlStatus`).

### 26. 심(shim) 공백은 **엉뚱한 오류 메시지**로 나온다
`scripts/dev/linux-render-typecheck.sh` 가 실패했을 때, 오류가 `linux-shim/` 의 `note:` 를 달거나
메시지가 `has no member` / `extra argument` / `missing argument` / `takes no arguments` /
`cannot find 'X'`(대문자 시작) 면 대개 **심 공백**이다. 그때는 테스트가 아니라
`scripts/dev/linux-shim/` 을 고쳐라.
**함정**: 생성자가 없으면 "인자 없는 호출에 인자를 넘겼다" 로 나오고 그 뒤 변수가 미해결이라
**파생 오류가 줄줄이 딸려 온다**(6줄 중 5줄이 파생인 경우도 있었다). **첫 줄만 보고 고쳐라.**

## 4. 검증 규율

### 4.1 격리 검증 — 여러 사람이 한 트리에서 일할 때
`git archive HEAD | tar -x -C <임시트리>` 로 깨끗한 트리를 만들고 **내가 고친 파일만** 이식해
테스트를 돌린다. 끝나면 `cmp -s` 로 원본과 대조해 **검증 이후 누가 건드렸는지**(드리프트) 본다.

이 패턴이 실제로 두 번 일했다:
- 근거 없이 바뀐 상수 하나를 잡아냈다(`WEDefaults.exponent` 가 2→3 으로 바뀌어 있었고
  같은 파일의 표와 모순이었다. 생성자를 직접 떠서 `mov dword ptr [rdi+0x2ec], 0x40000000` = 2.0f
  를 확인하고 되돌렸다).
- 남의 편집 때문에 난 빌드 실패를 "내 것이 아니다" 로 **증명**할 수 있게 했다.

**그런데 `--filter` 를 걸면 이 그물이 새 나간다.** `--filter 'GLSL|Shader'` 로 초록을 받고
푸시했는데 macOS CI 가 붉었다 — 뒤집은 규약(`#if` 소수 리터럴)의 **옛 단정을 들고 있던 세
번째 파일**이 `TranslationEvalFixRegressionTests` 라 필터에 안 걸렸다. 같은 사실을 잠그는
테스트가 어디에 더 있는지는 **파일 이름으로 짐작할 수 없다.**
→ 규약을 **뒤집는** 변경(옛 단정이 어딘가에 있을 수밖에 없는 변경)이면 **필터 없이 전 스위트**를
   한 번 돌리고 푸시해라. 필터는 반복 중의 빠른 되먹임용이지 **푸시 전 관문이 아니다.**
→ 값싼 사전 점검: 뒤집기 전 동작을 나타내는 **문자열**로 `Tests/` 를 통째로 grep 해라
   (예: `grep -rn "1\.5" Tests/`). 그게 세 번째 파일을 찾아 줬을 것이다.

**더 나쁜 경우: `WapleRenderTests` 는 리눅스에서 아예 안 돈다.** 타입체크만 된다. 그래서 그쪽의
**낡은 단정·낡은 픽스처**는 전 스위트를 돌려도 안 잡히고 macOS CI 에서야 터진다. 실제로 한
라운드에서 두 번 당했다:
- 합성 `MDLA0001` 픽스처가 옛 프레이밍으로 바이트를 짓고 있어, 파서를 실물에 맞추자
  **두 번째 클립의 이름이 `"clipB"` 가 아니라 `"B"`** 로 읽혔다(정확히 4바이트 잠식).
- 새로 넘겨받은 테스트가 `makeScriptEngine` 을 씬 컨텍스트 없이 불러 **간단 init 의 `update`
  관문**에 걸려 전건 nil 이었다.

→ **포맷 바이트를 손으로 짓는 픽스처는 리포 전체에서 찾아라.** `grep -rn '"MDLA0001"' Tests/`
   같은 **매직 문자열** grep 이 유일하게 믿을 만한 그물이다. 지금 `MDLA0001` 을 손으로 짓는
   테스트 파일은 **넷**이고 빌더가 넷 다 따로다 — 포맷이 바뀌면 넷을 같이 고쳐야 한다.
   (공유 빌더로 합치는 것이 옳지만 `WapleCoreTests`/`WapleRenderTests` 가 별 타깃이라
   테스트 지원 모듈이 필요하다. 미해결.)
→ `WapleRender` 를 건드리는 변경은 **타입체크 초록을 근거로 삼지 마라.** 그건 "컴파일된다"
   까지다. 값 단정은 macOS 가 판정한다.

### 4.2 빌드 락 — 동시 빌드 2개면 OOM 이다
4코어/16GB 컨테이너에서 `swift build` 두 개가 겹치면 컨테이너가 통째로 재시작한다(실제로 당했다).
`scripts/dev/linux-core-tests.sh` 와 `scripts/dev/linux-render-typecheck.sh` 는 **스스로**
고정 락 `${TMPDIR:-/tmp}/waple-swift.lock` 을 잡는다.
종전에는 후자가 락 경로를 **작업 디렉터리에서 유도**해서, 디렉터리가 다른 두 실행이 서로 다른
락을 잡아 **상호배제가 아예 안 됐다**(`/proc/locks` 로 두 락이 동시에 잡힌 것을 확인했다 —
그게 OOM 경로였다). 락을 갈아야 하면 `WAPLE_SWIFT_LOCK` 을 **명시**해라. 유도에 기대지 마라.

### 4.4 골든 스냅샷 — CI 에서 실제로 도는 것
렌더 산술을 고칠 때 "골든이 깨지나?" 는 매번 나오는 질문이다. 답:

- **CI 에서 도는 유일한 픽셀 골든은 `SyntheticPixelGoldenTests`** 다(128×72, 씬 5개,
  `spec/golden/synthetic/*.png`). 코드로 합성한 씬이라 코퍼스가 필요 없다.
  다섯 씬 모두 `general` 에 `hdr`·`bloom` 키가 없고 둘 다 기본 false 라
  `sceneWantsHDRBloom = doc.hdr && doc.bloom` 이 거짓 — **HDR 블룸 경로는 안 지난다.**
- **256×144 기준선**(`spec/golden/snapshot/baseline-*`)을 픽셀로 대조하는 것은 실물 코퍼스가
  필요한 맥 로컬 스크립트뿐이고 **CI 에는 호출부가 없다**. 스위트 안의
  `GoldenBaselineOracleTests` 는 manifest 를 자기 자신과 대조한다(렌더 무관).

→ **즉 렌더 산술을 바꿔도 CI 는 안 깨진다.** 하지만 256×144 재기준선 부채는 실재한다.
  화면이 바뀌는 변경을 하면 **바뀌는 범위를 반드시 세서 보고해라.**

### 4.4b VA 인용은 기계로 대조한다 — `scripts/re/va_citations.py`
`WE_ROOT` 를 주고 돌리면 `Sources`·`Tests`·`docs`·`spec`·`scripts/spec` 의 VA 인용을 전수로
훑어 **명령 경계인지** 본다. 어긋나면 어느 명령의 몇 바이트 안인지, `disp32` 위치인지,
주입본 주소인지까지 분류하고 원래 주소를 제시한다.

```bash
WE_ROOT=/path/to/wallpaper_engine python3 scripts/re/va_citations.py            # 전수
WE_ROOT=... python3 scripts/re/va_citations.py docs/re/tonemapping.md           # 일부
WE_ROOT=... python3 scripts/re/va_citations.py \
    --binary "$WE_ROOT/bin/webwallpaper64.exe" docs/re/web-wallpaper-bridge.md  # 다른 이미지
```

**`--binary` 는 장식이 아니다.** `wallpaper64.exe` 로만 재면 다른 이미지의 인용이 통째로
"명령 경계 아님" 으로 나온다. 실측: `docs/re/web-wallpaper-bridge.md` + 웹 관련 소스·테스트가
`wallpaper64.exe` 기준으로는 **153건**이었는데 `bin/webwallpaper64.exe` 로 재니 **3건**이 됐고,
그 3건 중 둘은 문서가 `wallpaper64.exe` 라고 **밝혀 둔** 줄이라 정상이었다. 남은 하나가 진짜였다
(`WallpaperBridgeJS.swift` 의 `0x14001f569` → `0x14001f568`, 그리고 그 주석은 **어느 바이너리인지  [VA-정정]
아예 안 적고 있었다**).

**툼스톤과 충돌하지 않게** — 줄에 마커를 넣으면 그 줄의 VA 는 판정에서 빠진다. 정정할수록
보고서가 더러워지는 모순을 없애면서, 면제가 **명시적**이라 heuristic 처럼 조용히 넓어지지 않는다.
마커는 셋이고 **뜻이 다르므로 섞어 쓰지 마라**:

| 마커 | 뜻 |
|---|---|
| `[VA-정정]` | 옛(틀린) 주소를 기록으로 남긴 자리 |
| `[VA-스캐너위치]` | 바이트 스캐너가 산출한 **`disp32`·변위 필드 위치** — 명령의 한 필드를 가리킨다 |
| `[VA-데이터표]` | `.text` **안에 박힌 데이터**(점프 표 · 인덱스 표) — 애초에 코드가 아니다 |

JSON 정본처럼 마커를 넣을 수 없는 자리만 도구 안의 `CORRECTION_LINES` 전문 일치나
(파일, 키)로 좁힌 `SCANNER_ADDRESS_FIELDS` 를 쓴다.

**[2026-08-21] 이제 맨몸 전수 스캔이 이미지를 스스로 고른다.** 종전엔 사람이 `--binary` 를
기억해서 줘야만 웹 경로가 오탐을 벗었고, 안 주면 그냥 붉었다. 도구 안에 표 둘을 뒀다:

| 표 | 뜻 |
|---|---|
| `BINARY_ROUTING` | 이 파일은 **이 이미지**로 재라(파일 → 이미지) |
| `BINARY_ALSO` | 한 이미지로 못 가르는 파일 — `--also` 로 **그 이미지들에서도** 경계인지 본다 |

전수 스캔은 표대로 그룹을 갈라 각자의 이미지로 재고 그룹별 요약을 따로 찍는다.
실측(HEAD 기준): 라우팅 전 **경계 이탈 134** → 라우팅 후 **19**. 줄어든 115건은 고쳐서가
아니라 **애초에 틀린 이미지로 재고 있었기 때문**이다.

**표에 넣을 이미지는 "이탈이 적은 쪽" 으로 고르면 안 된다.** `.pdata` 가 작은 이미지를 고르면
거의 모든 주소가 "데이터/리프" 로 빠져 검사 자체가 공허해진다(실측: `bin/scenescript64.dll` 은
어떤 파일을 줘도 이탈 0 을 낸다 — 경계 OK 도 0 이기 때문이다). 기준은 **경계 OK 가 압도적으로
많은 쪽**이다. 웹 클러스터 일곱 파일은 그 기준으로 전건 결정적이었다(경계 OK 18 → 79, 이탈 51 → 2).

**남은 한계**: 표는 **파일 단위**다. 한 파일이 여러 이미지의 주소를 섞어 인용하면 `BINARY_ALSO`
로만 다룰 수 있고, 그건 "어느 이미지에서든 경계면 통과" 라 그물이 그만큼 성기다.
→ 그러니 여전히 **주석·문서에 VA 를 적을 때는 어느 바이너리인지 밝혀라.** 안 밝히면 읽는
   사람이 같은 실수를 한다(실사례: `WallpaperSchemeHandler.swift` 의 zcompat 인용이
   `webwallpaper64.exe` 인데 안 적혀 있었다).

### 4.5 돌연변이 검증 — 테스트가 정말 그 사실을 잠갔나
고친 로직을 **일부러 틀린 값으로 되돌려** 보고 네 테스트가 실제로 실패하는지 확인해라.
안 잡히면 그 테스트는 아무것도 잠그지 않은 것이다. 확인 후 반드시 되돌려라.

**주입 자체가 무효일 수 있다.** 실사례: 마스크에 상위 비트를 더하는 돌연변이를 넣었는데
코드가 `& e.bit` 로 읽어서 **여전히 매치**했다 — 즉 그 돌연변이는 동작을 안 바꿨다.
무효임을 확인하고 never-match 로 다시 주입해서야 잡혔다. **돌연변이가 안 잡히면
"테스트가 약하다" 와 "내 돌연변이가 무효다" 를 먼저 갈라라.**

### 4.6 CI 테스트 수 하한
`.github/workflows/ci.yml` 이 실행 테스트 수의 하한을 박아 둔다(테스트가 조용히 사라지거나
스위트가 중간에 죽는 것을 잡는다). 하한은 **CI 가 초록으로 실제 측정한 수**에만 맞춰 올려라.
정적 개수는 `grep -rE '^\s*(public |private |internal )?func test' Tests/ --include=*.swift | wc -l`.
현재 하한 **3500**(2026-08-21, `2d19faa` 초록 실행 실측 `executed=3596 skipped=65`).
여유는 **100 안쪽**으로 유지해라 — 종전 여유 246 은 테스트 파일 하나가 통째로 안 실리는
양상(대개 100건 이상)을 못 잡는 폭이었다. 같은 스텝의 **스킵 상한 100** 과 짝이다: 하한은
"사라진 것", 상한은 "스킵으로 위장한 것"을 잡는다.
