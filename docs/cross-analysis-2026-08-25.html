구조와 규모

  • 외부 디펜던시 제로 — Package.swift에 .package 선언 자체가 없음. Apple 프레임워크만 사용(Package.swift:22-89)
  • 명확한 4단 DAG, 순환 0건 — Policy/Snapshot(L0) → Core(Foundation+simd만) → Library·Render → CompatCore → App/Compat(L3). 전수 grep에서 역방향 import 0건
  • WapleCore 29,564줄 + WapleRender 25,527줄 = 프로덕션의 81%. 테스트는 7타깃 337파일, func test 3,700개(XCTest 100%)
  • WapleSaver는 빈 모듈이 아니라 SPM 밖 ObjC — WapleSaverView.m(152줄)을 package-app.sh가 clang -bundle로 직접 컴파일(SPM은 .saver 번들 타깃 불가)
  • OggVorbis·TEX/DXT5 디코더·GLSLTranslator(2,573줄)·ParticleSimulator(2,298줄) 전부 자체 구현 — WapleCore에는 Foundation+simd import만 존재

지식 정본 문화 — 이 코드베이스의 가장 특이한 강점

  • wallpaper64.exe 디스어셈블 VA가 코드 주석에 수천 개 인용. “오역보다 폴터” 원칙 — ShaderPreprocessor는 미지원 #if에서 조용한 오분기 대신 번역 실패를 택함
  • 정정 이력이 툼스톤 주석으로 남음 — “종전 판정의 근거는 지금도 맞지만 결론을 뒤집는다” 패턴 반복(visibilityParent, spriteTrailStretch 철회 등)
  • 109개 테스트 파일이 VA 리터럴을 단언, 음성 대조(negative control)가 표준 절차 — 게이트가 진짜 걸러내는지 빨강 프레임으로 확인하는 문화
  • jsoncpp 타입태그 재현(isJSONBool objCType 0x63, 관용폭 3단 사다리, 32비트 폭 축 wrapInt32/wrapUInt32)이 JSON 로딩의 공통 기반 (JSONNumerics.swift:170-323)

렌더러·앱 한눈에

  • MTKView 라이브 렌더 + 오프스크린 acc 합성 — draw()는 가림 게이트·dt 클램프(50ms) 후 z-order 인터리브 드로우, finalizeScene에서 HDR 블룸 또는 blit 프레젠트(SceneRenderer.swift:2246-2422)
  • GLSL→MSL 4단 번역 + 프로세스 전역 메모이즈, EngineU 80-float 유니폼 버퍼(buffer(1)). mul(a,b)→(b*a) 행우선 전치 등 변환 규약 확정
  • 결정성 계약 전역 적용 — 헤드리스 캡처는 벽시계·Math.random(mulberry32)·포인터·오디오·비디오를 전부 핀

교차 대조 — 통합 판정

양쪽 16레인 결과를 기능 영역별로 “Waple 상태 × WE 증거 강도” 2축에 세운 결과

포맷 계약 축(pkgv/scene/project/tex/mdl/glsl)은 WE 증명 ↔ Waple 구현이 맞닿아 있다. 실제로 어긋나는 지점은 ‘구현 품질’이 아니라 ‘배선’(재생 정책, application 유형)과 ‘WE 증거 공백’(파티클 산식, script API, 라이팅 세부, 비디오 클록)이다. JSON 파서 3종 병존 확정은 WapleCore의 중복키 [미해결]을 부분적으로만 닫고, MDL stride 앵커는 아직 미소비 — TEX/MDL은 Waple이 WE 가설을 앞서 구현해 교차 검증 없이 굴러가는 상태이므로 최종 검증이 배포 리스크 관리의 핵심이다.
