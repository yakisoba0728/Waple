# Waple — 의도적 이탈 3건 A/B 캡처

**목적: 이탈을 제거했을 때 화면이 어떻게 달라지는지 실측한다.** 그 결과로 유지/제거를 정한다.

이탈 셋 다 `[0,1]` 입력에서는 WE 와 **등가**고 경계 밖(HDR >1 / 음수)에서만 갈린다.
그래서 A/B 는 **HDR 씬에서만 달라져야 하고, 비-HDR 씬은 완전히 같아야 한다.**
비-HDR 이 바뀌면 패치가 의도 밖 경로를 건드린 것이다 — 그게 이 실험의 대조군이다.

---

## ⚠️ 먼저 알아야 할 것 두 가지

### 1. Metal 은 GUI 로그인 세션에서만 잡힌다
SSH 로 들어와 그냥 실행하면 GPU 작업이 **실패가 아니라 조용히 스킵**된다.
- Mac 이 **콘솔에 로그인**돼 있어야 한다(화면 잠금은 무관, 로그인 화면이면 불가)
- GPU 명령은 `launchctl asuser $(id -u) ...` 로 감싼다
- `01-check-env.sh` 가 검사한다. 통과 못 하면 진행하지 마라

### 2. 골든 게이트를 믿으면 안 된다 — 대상의 절반이 사각지대다
`WapleCompat --compare` 의 strict 임계가 **절대 단위**(평균 절대차 1.5/255)라
어두운 씬에서 사실상 무력하다. 실측으로 **전면 검정으로 바꿔도 통과하는 씬이 3종** 있다.

D1/D2 대상 4종 중 **`3470948192` · `3662790108` 이 그 사각지대**다.
그래서 이 실험은 `--compare` 를 쓰지 않고 **`03-ab-diff.py` 가 썸네일을 직접 읽어
픽셀 통계를 낸다.** 상대 지표(대비 정규화)를 함께 내므로 어두운 씬도 판정된다.

## 순서

```bash
git clone -b feat/we-engine-port-design   https://github.com/yakisoba0728/Waple.git ~/Desktop/Waple
cd ~/Desktop/Waple/scripts/ab-deviations

bash 01-check-env.sh          # 환경 + Metal + 리포 + A 기준선 확인
bash 02-capture-ab.sh         # 이탈 제거 패치 → B 캡처 → 패치 되돌리기
python3 03-ab-diff.py         # A(기준선) vs B 픽셀 통계
```

스크립트가 리포 안에 있으므로 **경로는 자기 위치에서 유도**한다. 어디에 clone 하든 동작한다.

`02` 는 패치를 적용하고 캡처한 뒤 **자동으로 되돌린다**. 중간에 실패해도
`git checkout` 으로 원복하니 리포가 더러워지지 않는다.

## 보고할 것

`03` 이 출력하는 표를 그대로 보내주면 된다. 판정에 필요한 건 이것들이다:

1. **HDR 대상 씬이 실제로 바뀌었는가** — 안 바뀌었으면 이탈이 코퍼스에서 무의미하다는 뜻
2. **대조군(비-HDR)이 안 바뀌었는가** — 바뀌었으면 패치가 잘못됐다
3. **바뀐 방향** — 밝아졌나 어두워졌나, 어디가(순백 클리핑? 검정 뭉개짐?)
4. **사각지대 2종의 상대 지표** — 절대 평균차로는 안 보이는 변화가 있는가
